## 项目环境注意

- 仓库当前 **没有 node_modules**（本地），无法运行 `npm run lint` / 构建。改动只能靠人工审查 + CI 反馈。
- 构建使用 `ts-loader`（非 transpileOnly），**会做完整类型检查**，类型错误直接导致构建失败；主进程构建还挂了 `ESLintPlugin`。
- eslint 用 `standard-with-typescript`（`.eslintrc.base.cjs`），是 type-aware 规则集。注意：
  - 返回 Promise 的箭头函数需要 `async` 或加 `// eslint-disable-next-line @typescript-eslint/promise-function-async`（仓库里已有先例）。
  - 避免 `no-unnecessary-condition` 类问题：不要对非可空类型用 `?.`。

### 踩坑：httpFetch 返回值没有 promise 属性（TS2339）

`src/renderer/utils/request.js` 是 JS 文件，`buildHttpPromose` 里 `obj.promise` 是**动态追加**的属性，TS 推断出的类型只有 `{ isCancelled, cancelHttp }`，所以在 .ts 里写 `httpFetch(...).promise` 会报
`TS2339: Property 'promise' does not exist on type '{ isCancelled: boolean; cancelHttp: () => true | undefined; }'`。
（.vue 里这么写不会报错，因为 vue 文件不走这个类型检查路径。）

正确写法（本次采用）：

```ts
interface HttpFetchResult { promise: Promise<{ body?: unknown }> }
const request = httpFetch(url, { follow_max: 3, timeout: 20_000 }) as unknown as HttpFetchResult
const script = (await request.promise).body
```
